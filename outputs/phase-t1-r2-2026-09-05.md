## Befund 1 — Flex-Tarife: nachgemessen statt per Config beschnitten

Der Evaluator bemängelte, `max_dokumente: 5` an der `telekom_kacheln`-Quelle
schneide die vier Flex-Varianten weg, gestützt auf `QUELLEN_MAP.md`s Angabe
„Flex ×10" (Messung 04.09.2026). Diese Runde hat das **selbst nachgemessen**,
nicht nur die Config-Zahl erhöht.

### Was „Flex ×10" wirklich ist

`QUELLEN_MAP.md` zählt an dieser Stelle rohe Textvorkommen des Wortes
„Flex" auf der Seite — keine Preiskacheln. Nachgezählt auf derselben Seite
(`/shop/tarife/handyvertrag`, frischer Abruf 05.09.2026): das Wort „flex"
kommt **484-mal** vor, ganz überwiegend als CSS (`display:flex`), als
Navigations-/Routing-Konfiguration (`smartphone-tarife-flex`,
`internet-tarife-flex` als Kategorie-Slugs) und als Marketing-/Rechtstext
(„Flexibel bleiben …"). Die Zahl aus der QUELLEN_MAP war eine Substring-
Zählung aus der ersten Erkundung, keine Kachel-Zählung.

### Drei eigene Gegenproben, alle negativ

1. **Frischer Abruf derselben Seite.** `TariffTileModified_
   TariffTileModified__<hash>` (der Kachel-Wrapper, den der Adapter liest)
   kommt **genau fünfmal** als echtes HTML vor — XS/S/M/L/XL, keine sechste
   Kachel. Identisch mit dem Stand aus Runde 1 (Fixture vom selben Tag,
   sha256 `e4353c05…`, jetzt gegen einen taufrischen Abruf gehalten).
2. **`__INITIAL_STATE__` rekursiv durchsucht.** Jeder Schlüssel, der
   „flex" enthält, geprüft, ob ein Geschwisterwert wie ein Preis aussieht:
   `tariffv2.currentTariffs` ist `[]`, `productList.data` ist `[]`. Eine
   volltextliche Suche nach jeder Zeichenkette, die „flex" UND eine Zahl
   mit Komma/Punkt trägt, ergab 16 Treffer — ausnahmslos
   Übersetzungstexte und MagentaEINS-Rechtstexte
   (`translation.cart.global.magentaOneDiscountDetailsModal.*` u. Ä.),
   keiner ein strukturierter Tarifpreis.
3. **Die naheliegenden Alternativ-Adressen einzeln abgerufen:**
   - `https://www.telekom.de/shop/tarife/smartphone-tarife-flex`
     (dieselbe Routen-ID, die im JSON-State als eigene Kategorie geführt
     wird): HTTP 200, 2,02 MB, **null** Treffer auf die Kachel-Klasse,
     keine `MagentaMobil`-Kachel überhaupt.
   - Die acht Flex-Tarif-Detailseiten `magenta-mobil-{xs,s,m,l,xl}-flex`
     und `magenta-mobil-data-{s,m,l}-flex`
     (`https://www.telekom.de/shop/tarif/<slug>`): alle HTTP 200,
     1,60–1,61 MB. Keine trägt die Kachel-Klasse. Das einzige `ld+json`
     jeder Seite ist `BreadcrumbList` + `Organization` + `FAQPage` — kein
     `Product`-/`Offer`-Knoten. Zur Gegenprobe dieselbe Prüfung an der
     NICHT-Flex-Detailseite `magenta-mobil-s`: derselbe Befund (keine
     Kachel, kein Produkt-ld+json) — Detailseiten tragen bei dieser Quelle
     grundsätzlich keinen Preis, unabhängig von Flex.

### Ergebnis

Flex-Tarife sind auf dieser Domain mit ehrlichen Mitteln (kein
JS-Rendering, kein Impersoning) **nicht live messbar** — das ist eine
gemessene Grenze der Quelle, keine Konfigurationsentscheidung. `config/
tarif_quellen.yaml` trägt jetzt trotzdem `max_dokumente: 12` statt `5`
(Kommentar mit dieser Messung ergänzt): die Zahl 5 sah nach einer Kappung
aus, obwohl sie schon vorher exakt der realen Kachelzahl entsprach. Mit
Headroom ist unmissverständlich, dass eine künftige sechste/siebte Kachel
nicht an dieser Zahl scheitern würde. Ein Selektor-Umbau entfällt, weil es
auf der Seite kein zweites, unentdecktes Markup für Flex-Kacheln gibt.

Die vier Flex-Tarife bleiben PDF-versorgt (Stand 2021, wie in Runde 1
dokumentiert) — kein stiller Mangel: ihr Datensatz trägt sein eigenes
`abgerufen_am`/`versionsstand`, und `tarife.html`/`geraete.html` verlinken
sie unverändert direkt (kein „(Referenz)"-Etikett, weil keine Live-Zeile
existiert, die sie ablösen könnte — dieselbe Regel wie in Runde 1 für
„MagentaMobil Basic").

**Nebenbefund (nicht Teil dieses Auftrags, hier nur benannt):** die
Tarif-Tabelle auf `tarife.html` zeigt pro Zeile nur dann ein Datum, wenn
eine Live-Zeile ein Pflichtdokument zurückgestuft hat (`z.referenz_stand`).
Für eine reine PDF-Zeile ohne Live-Pendant — wie die vier Flex-Tarife —
erscheint auf der Seite selbst **kein** Datum, nur der globale Kopf „Stand
{{ tarife.stand }}" (das jüngste Datum über alle Zeilen). Das ist ein
vorbestehendes Verhalten (unverändert seit vor Runde 1) und nicht Gegenstand
der zwei Befunde dieses Auftrags; wer die Sichtbarkeit von Alt-Ständen auf
der Website selbst verbessern will, braucht ein eigenes, kleines Ticket
(`z.stand` zusätzlich in `tarife.html.j2` rendern).
